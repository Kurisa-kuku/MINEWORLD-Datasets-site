# 快速开始

每个条目就是 [`data/datasets`](https://github.com/Kurisa-kuku/MINEWORLD-Datasets-site/tree/main/data/datasets) 里的一个 JSON 文件，外加一张封面。你不需要仓库写权限：提交流程通过 GitHub Issue Form 和自动 Pull Request 完成。

## 开始之前

你需要：

- 一个 GitHub 账号；
- 稳定可用的下载链接，或申请访问的联系方式；
- 中英双语的标题和一句话短描述；
- 许可证，以及在该许可证下再分发的权利；
- 16:9 封面（建议 1280×720，最大 2 MB）；
- 对已知限制的诚实说明。

> 数据集**不一定要**用 Mwarecorder 录制。回放、原始视频、已经整理好的自定义数据集都欢迎。Mwarecorder 只是提供最完整的默认对齐。

## 1. 打开提交表单

进入 **提交** 页面，点击 **打开提交表单**。这是 GitHub 官方 Issue Form，字段结构化，方便目录检索，而不是依赖自由文本。

表单包括四组内容：

1. **基本信息**：中英标题、短描述、License、封面。
2. **来源与兼容**：格式、Mwarecorder 版本、数据流、环境。
3. **规模与内容**：episode 数、总大小、总时长、任务 / 维度 / 训练用途 / 质量标签。
4. **访问与合规**：下载链接、访问类型、隐私三连问。
5. **使用说明**：如何加载、推荐用法、已知限制、可选示例。

## 2. 添加封面

封面字段接受图片 URL，也可以把图片拖入文本框（GitHub 会自动上传并插入链接）。

- 16:9，建议 1280×720。
- 处理前不超过 2 MB。
- 工作流会下载图片、裁切为 16:9、转换为 WebP，并生成 640×360 缩略图。
- 如果不提供封面，网站会根据 slug 从四张像素默认封面中稳定地选一张。

不要上传你无权使用的图片。自己世界的截图是最合适的。

## 3. 自动化会做什么

当 Issue 创建或编辑时：

1. `issue-to-pr.yml` 解析结构化表单。
2. 使用 `schemas/dataset.schema.json` 校验字段。
3. 将封面转换为 WebP，并生成缩略图。
4. 在 `data/datasets/` 下新增 JSON 文件。
5. 自动打开 Pull Request，并回链到 Issue。

工作流不会直接提交到 `main`，也不会自动合并。

## 4. 审核

维护者会检查：

- 许可证和再分发权利；
- 隐私声明；
- 链接有效性与访问类型；
- 中英标题和描述质量，以及语言回退；
- 数据描述与实际文件是否一致。

你可能被要求编辑原始 Issue。再次运行工作流会更新自动生成的分支和 PR。合并后网站会自动重新构建。

## 5. 发布之后

你的条目会获得：

- 固定的 `/en/datasets/<slug>/` 与 `/zh/datasets/<slug>/` 页面；
- URL 同步的筛选与搜索；
- GitHub reactions 与 Giscus 评论；
- 把元数据修改转换成 Pull Request 的更正流程；
- 版本历史，以及可选的弃用 / 替代关系。

## 常见驳回原因

- 下载链接需要私有令牌或 Google Drive 权限申请。
- License 写着 CC BY，但归档包含未署名的第三方模组素材。
- Episode 数或时长是估算，不是根据实际文件统计。
- 已知限制写着“无”，但录制过程中出现丢帧或多次暂停。
- 封面是拉伸的截图或未授权的 Logo。

如果审核只发现小的元数据错误，维护者会让你使用[元数据编辑器](../corrections/)，而不必重新提交整个表单。
