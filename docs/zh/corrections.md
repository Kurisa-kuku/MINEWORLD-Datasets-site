# 更正与生命周期

数据的寿命长于它第一次被描述的时候。许可证变化、归档重新索引、镜像失效，或者新录制替代了旧版本。目录把元数据当作有版本控制的源代码。

## 使用元数据编辑器

打开任意数据集并选择 **编辑元数据**，或访问 `/en/edit/` / `/zh/edit/`。贡献者可以修改：

- 中英标题与短描述；
- License、格式与兼容字段；
- 数据流、环境与校验状态；
- episode 数、总大小与时长；
- 任务、维度、训练用途与质量标注；
- 访问类型、下载链接与隐私回答；
- 双语使用说明与示例。

编辑器刻意**不修改** slug、封面、贡献者列表或版本历史。这些需要随数据一起审核。封面或署名如有变更，请在更正说明中提出。

## 提交之后会发生什么

编辑器会：

1. 在本地构建完整的修正 JSON。
2. 创建一个带机器可读标记的 `[Correction] …` Issue，正文包含 JSON。
3. 留下供审核者阅读的变更说明。

issue-to-pr 工作流检测到更正标记后，会校验 JSON、写入更新后的文件、追加变更记录，并打开 Pull Request。之后由维护者检查 diff。

在 PR 合并并完成部署之前，线上网站不会改变。

## 变更记录规则

任何改变实际归档的发布都应该在 `history` 中追加日期、可选版本号和双语说明。仅元数据的更正也会追加一条历史记录；自动化会写入通用说明，并在可能时附上 Issue 链接。

更正不应改写历史。需要下线旧版本时，请标记弃用，而不是删除记录。

## 替代一份数据集

当新数据集替代旧版本时：

1. 发布新条目；
2. 编辑旧条目；
3. 把 `deprecation.status` 设为 `superseded`；
4. 把 `deprecation.replacedBy` 设为新 slug；
5. 在 `deprecation.note` 与历史记录中说明原因。

旧 URL 会保持有效，并显示指向新数据集的提示条。这对于引用原始条目的论文和训练日志非常重要。

如果数据集因合规或质量原因撤下，可使用不带替代者的 `deprecated`。记录仍然可见，避免被删除的数据被误认为有效数据。

## 举报而不是更正

如果问题不是简单的元数据修改——例如链接失效、许可证违规或隐私风险——请使用 **举报问题**，而不是编辑器。举报会进入管理队列并公开。不要在举报中粘贴隐私数据；描述问题，维护者会在需要时私下跟进。

## 谁可以提交更正？

任何有 GitHub 账号的人。你不需要仓库写权限。自动化会代为打开 Pull Request，由维护者审核。原始上传者提交的更正会通过 GitHub 作者身份自动区分。
